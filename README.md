# Who Wrote It? Identifying LLMs from Their Responses

CMPSC 448 Midterm Project  
Author: Qihaohan Zheng(Solo)

This project uses a convolutional neural network (CNN) and a bidirectional LSTM to classify responses by their recorded source family: **Claude, DeepSeek, or GPT**. It investigates attribution accuracy, the value of prompts, cross-domain generalization, and descriptive text features.

## Research Questions

- **RQ1:** Can the source LLM be identified from its response?
- **RQ2:** How do input-only, output-only, and input + output classification compare?
- **RQ3:** Do classifiers trained on Coding, Math, and Factual tasks generalize to Writing?
- **RQ4:** How do response length, lexical diversity, and formatting differ across the collected sources?

## Dataset

The dataset contains **300 shared English prompts and 900 responses**, with one response per prompt from each source family. Each of six categories contains 50 prompts: Factual, Explanation, Math, Coding, Writing, and Summarization.

Prompts have manually assigned difficulty labels; these labels are not empirically validated. The prompt bank was designed with LLM assistance. The summarization passages were created for this project.

The merged CSV contains:

```text
response_id,prompt_id,LLM_name,model_version,LLM_Input,LLM_output,category,task_type,difficulty
```

Exact model versions and complete collection settings were not preserved in the reviewed records. Source labels should therefore be interpreted as recorded families, not verified version identifiers. Collection reproducibility is limited by this missing metadata.

### Main Partitions

| Partition | Unique prompts | Responses | Responses per family |
|---|---:|---:|---:|
| Training | 210 | 630 | 210 |
| Validation | 45 | 135 | 45 |
| Test | 45 | 135 | 45 |

Splits use seed 42 and preserve category balance approximately. All three answers to a prompt remain together, and prompt IDs do not overlap across partitions. Vocabulary fitting and sequence-length selection use training data only.

## Installation

Use a Python environment compatible with the installed PyTorch version. The recorded experiment runtime was **PyTorch 2.14.1+cpu**; exact Python and other dependency versions were not recorded.

Install the required packages in the same interpreter used to run the project:

```bash
python -m pip install torch scikit-learn matplotlib
```

CPU execution is supported. The training script selects CUDA automatically when available; CPU and GPU results may differ. No API keys or paid API access are needed to train on the collected CSV files.

### PyCharm Setup

1. Open the project root as a PyCharm project.
2. Select an existing Python interpreter or create a project virtual environment.
3. Install dependencies using that interpreter.
4. Keep scripts in `scripts/` and source CSVs in `data/`.
5. Run the scripts in the order below.

Paths are resolved relative to the scripts, so they do not depend on the terminal working directory. `train_rq2.py` and `run_rq3.py` import `train.py`; keep all three in the same directory.

## Running the Project

Run these commands from the project root, or run each script directly in PyCharm.

### 1. Merge and Validate Responses

```bash
python scripts/merge_responses.py
```

Reads the prompt bank and three response CSVs, assigns source-family labels, and writes `data/raw_responses.csv`. Checks include missing IDs, duplicate IDs, empty responses, and exact input agreement. These checks do not establish response correctness or completeness.

### 2. Create Prompt-Grouped Splits

```bash
python scripts/split_dataset.py
```

Writes partitions to `data/splits/`. The script expects six categories containing 50 unique prompts each, with one response per family for every prompt.

### 3. Run RQ1: Output-Only Classification

```bash
python scripts/preprocess.py
python scripts/train.py
```

Preprocessing converts response text to padded integer sequences. Training fits CNN and LSTM models and saves minimum-validation-loss checkpoints. Results are written to `results/output_only/`.

### 4. Run RQ2: Alternative Input Conditions

```bash
python scripts/preprocess_rq2.py
python scripts/train_rq2.py
```

Runs Input-only and Input + Output experiments. The combined condition uses separate prompt and response budgets plus a separator token. The comparison script includes the existing Output-only summary when available. Run RQ1 first to obtain all six rows in `results/rq2_comparison.csv`.

### 5. Run RQ3: Cross-Domain Evaluation

```bash
python scripts/run_rq3.py
```

Trains new Output-only models on Coding, Math, and Factual tasks. Source-domain partitions contain 315 training, 66 validation, and 69 test responses. All 150 Writing responses form the cross-domain evaluation. Writing does not participate in vocabulary fitting, length selection, or checkpoint selection. The same selected model is evaluated in both test conditions.

Results are saved to `results/rq3/`. In the CNN/LSTM subdirectories, ordinary classification reports and predictions refer to the source-domain test; files starting with `cross_domain` refer to Writing.

### 6. Run RQ4: Descriptive Feature Analysis

```bash
python scripts/analyze_rq4.py
```

Produces per-response features, model/category/partition summaries, matched-prompt differences, and `rq4_features.png` in `results/rq4/`. This is post-training descriptive analysis over all 900 responses, not training-only feature selection.

**Rerunning scripts can overwrite their generated outputs.** Keep a copy of reported results before experimenting with new settings. Do not use test results to repeatedly tune hyperparameters.

## Models and Training

| Component | CNN | Bidirectional LSTM |
|---|---|---|
| Embedding | 128 dimensions; learned from scratch | 128 dimensions; learned from scratch |
| Encoder | Kernels 3, 5, 7; 64 filters each | 64 hidden units per direction |
| Representation | ReLU, masked max pooling, concatenation | Concatenated final directional states |
| Dropout | 0.5 | 0.5 |
| Output | Linear layer with three logits | Linear layer with three logits |

Both models use cross-entropy loss, Adam, learning rate 0.001, weight decay 0.0001, batch size 32, and gradient clipping at norm 1.0. Training runs for at most 30 epochs with patience 5 and seed 42. Checkpoints are selected by minimum validation loss. The LSTM uses packed sequences; CNN pooling excludes positions centered on padding.

The main Output-only vocabulary contains 5,153 entries and uses 160-token sequences. RQ3 fits a separate 2,234-entry vocabulary and uses 130-token sequences. Input conditions fit their own training vocabularies and sequence budgets.

## Results

### RQ1 and RQ2

| Model | Input condition | Test accuracy | Macro-F1 |
|---|---|---:|---:|
| CNN | Input-only | 33.33% | 0.3043 |
| CNN | Output-only | **65.19%** | **0.6476** |
| CNN | Input + Output | 61.48% | 0.6092 |
| LSTM | Input-only | 33.33% | 0.3222 |
| LSTM | Output-only | 51.85% | 0.4930 |
| LSTM | Input + Output | 43.70% | 0.4314 |

Output-only was the strongest condition for both architectures in this run. Input-only accuracy is exactly one third because each identical input occurs under all three labels: a deterministic classifier makes the same prediction for each group and gets one record correct. Adding prompts did not improve performance, but vocabulary and sequence-length changes prevent isolating the effect of prompt inclusion.

### RQ3

| Model | In-domain accuracy | Writing accuracy | Accuracy change | In-domain macro-F1 | Writing macro-F1 |
|---|---:|---:|---:|---:|---:|
| CNN | 69.57% | 48.67% | -20.90 percentage points | 0.7001 | 0.4924 |
| LSTM | 57.97% | 38.67% | -19.30 percentage points | 0.5823 | 0.3461 |

The unknown-token rate increased from 14.66% in the source test to 36.56% in Writing. Sixty of 150 Writing responses were truncated, compared with none of the 69 source test responses. Domain-specific patterns, vocabulary coverage, and truncation may all contribute to the decrease.

The CNN achieved its highest Writing class F1 for DeepSeek (0.58). The LSTM predicted Claude for 117 of 150 Writing responses, indicating a strong class bias rather than reliable Claude attribution.

### RQ4

| Feature | Claude | DeepSeek | GPT |
|---|---:|---:|---:|
| Mean characters | 357.8 | 196.2 | 355.6 |
| Mean English words | 57.4 | 31.2 | 54.8 |
| Mean MATTR-50 | 0.773 | 0.792 | 0.821 |
| MATTR-50 eligible responses | 153 | 43 | 123 |
| Responses with lists | 2.7% | 1.7% | 3.7% |
| Responses with Markdown headings | 0% | 1.0% | 0% |
| Responses with code fences | 0% | 0% | 17.0% |

DeepSeek responses were shorter, while GPT more often used Markdown code fences. These descriptive differences may help explain attribution, but no ablation established which features the networks actually used.

MATTR-50 measures unique-word proportions over sliding windows of 50 lowercased English words after removing fenced code. Short responses are excluded, so averages use unequal subsets. Unfenced code remains. Lists, headings, and fences are detected by specific Markdown patterns; absence of a fence does not mean absence of code.

## Limitations

- **Collection artifacts:** Sixty-three DeepSeek responses contain literal newline/tab escape patterns; none were flagged for the other sources. Classification retains them, while RQ4 heuristically restores them. They may provide a serialization shortcut, and restoration may affect intentional code escapes.
- **Incomplete provenance:** Exact model versions, generation settings, and complete collection boundaries are unavailable.
- **Small, single-seed experiments:** Differences have not been shown statistically significant or stable across seeds.
- **Overfitting:** Both Output-only models show training/validation gaps; checkpoint selection uses validation loss.
- **Representation differences:** Input conditions use different vocabularies and lengths. Cross-domain Writing has more unknown and truncated tokens.
- **Restricted generalization:** Only one cross-domain direction is evaluated. Writing is unseen by the new RQ3 models but some records were used in earlier mixed-domain experiments.
- **Descriptive explanations:** RQ4 does not establish causal feature importance or intrinsic model-family style.
- **Incomplete auditing:** Answer correctness, instruction compliance, and collection-time truncation were not systematically assessed.

The findings support attribution within this collected dataset, not a universal LLM detector. Future work should use verified versions, consistent collection, fresh held-out data, multiple seeds, normalization controls, and feature ablations.
